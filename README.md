# AgroDrone Monitor

Учебный проект для внутривузовского хакатона **AgroDataCode** (РГАУ–МСХА им. К. А. Тимирязева, 2026).
Тема — **«Агродроны и дистанционный мониторинг»**.

Веб-приложение, которое моделирует работу парка агродронов: дроны облетают поля, собирают показания датчиков (влажность, температура, NDVI), а оператор видит на дашборде карту здоровья посевов, очередь задач и состояние парка.

## Стек

- **Backend:** Go (стандартная библиотека `net/http`, без фреймворков)
- **Frontend:** HTML + CSS + чистый JavaScript (Canvas API для карты поля)
- **Хранилище:** in-memory (структуры данных в оперативке, без БД)

## Возможности

- Парк дронов с разными типами (разведка / опрыскивание) — наследование через встраивание структур.
- Поля как 2D-сетка клеток с показаниями датчиков.
- Очередь задач с приоритетом (heap).
- Пошаговая симуляция «тик = 1 час»: дроны летают, сканируют, разряжаются, заряжаются.
- Поиск связных проблемных зон на поле (BFS).
- Сортировка полей по индексу проблемности.
- Бинарный поиск по каталогу полей.
- Веб-дашборд с визуализацией карты поля и состоянием парка.

## Архитектура

```
agrodrone/
├── cmd/server/        # точка входа, запуск HTTP-сервера
├── internal/
│   ├── models/        # доменные сущности (Drone, Field, Cell, Task)
│   ├── storage/       # хранилища (map дронов, каталог полей, очередь задач)
│   ├── algo/          # алгоритмы (бинпоиск, сортировка, BFS)
│   ├── sim/           # движок симуляции
│   └── http/          # HTTP-обработчики, REST API
├── web/               # фронт (index.html, style.css, app.js)
├── go.mod
└── README.md
```

Слои не зависят друг от друга «вверх»: модели не знают про HTTP, алгоритмы не знают про хранилище. Папка `internal/` — Go-стандарт: эти пакеты нельзя импортировать из других модулей.

## Запуск

Нужен Go 1.22+.

```bash
git clone https://github.com/<user>/agrodrone.git
cd agrodrone
go run ./cmd/server
```

Откройте в браузере: <http://localhost:8080/>

Проверка, что сервер живой: <http://localhost:8080/api/ping>
